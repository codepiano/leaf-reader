# 扫描来源与导入书库

侧栏分别提供“扫描目录”和“书库设置”。扫描目录是可配置的多个来源路径；导入书库目录是可选复制的目的地。两套配置独立持久化，互不替换。

在“扫描目录”中添加路径，按“仅保存”只保存配置，按“保存并扫描”递归发现 EPUB 并加载到书架。扫描只读取元数据，不复制或移动原文件，不创建阅读会话，不修改最近阅读时间。新书显示“尚未阅读”。重复和重叠路径去重，已有记录保留进度、标签、收藏及合集划分。书架工具栏的“刷新”直接重扫已保存的来源目录，更新原书的书名、作者与章节数，并重新按需加载封面。手动补全的信息优先保留，阅读进度、时长、最近阅读时间、分组、标签、收藏、置顶和合集划分不会重置。外部改写 EPUB 后，正在阅读的会话保持原样，重新打开书籍时读取新内容；已有合集边界不会自动重新划分。

刷新期间按钮显示“刷新中…”并防止重复扫描，完成后显示新增、更新、已有、文件不可用与失败数量。当前搜索、排序和筛选保留。缺失或扫描时无法解析的文件标记“文件不可用”，记录保留；恢复原路径后再次刷新可恢复。文件移动到新路径时视为新记录，不自动猜测合并。没有配置来源目录时，刷新检查现有文件状态，并提示添加扫描目录。

导入默认关闭。关闭时打开书架中的来源书籍直接读取原路径；主动开启并配置导入书库后，通过书架、打开按钮或拖拽打开阅读时才复制到书库。内部章节/子书跳转不重复触发导入，书籍已在书库目录下时直接读取。复制保留原文件，并沿用已读原书的进度和整理信息。

扫描原路径与导入副本之间保留来源映射，防止扫描把已导入的来源重复加到书架。再次改变导入目的地时映射随记录迁移。若副本已经不存在，仍可通过扫描找回原目录中的源文件；旧缺失记录保留，不自动删除用户记录。

启动仅加载已有缓存，不执行全盘扫描；新增文件需要点击“刷新”或手动再次扫描。移除来源目录仅取消后续扫描，不删除书架记录或磁盘文件。读取目录/单本 EPUB 失败时继续处理其他条目并显示失败详情（最多展示 50 条）。最多配置 32 个来源，单次扫描最多处理 100,000 个目录项、10,000 个 EPUB；达到上限明确显示未完成提示。不会遍历目录内的符号链接。

扫描在 Rust 阻塞工作线程执行；文件 IO 期间不持有阅读会话锁或书架锁。结束时与最新书架合并，一次原子写入保存，不覆盖扫描期间产生的阅读进度和整理变更。逐本读取 EPUB 索引和元数据，不把所有正文解压到内存。

## 验证

开发及验证在独立工作树完成，依赖和 Cargo 输出为独立物理副本；浏览器验证使用端口 1438、新 origin 和 mock 数据，未扫描或复制用户个人书籍。验证期间线上 dev 的 Vite 与 Rust 进程保持不变。

- 17 个 Rust 测试通过，另 1 个 fixture 导出器默认忽略。覆盖多来源、递归、重叠根目录、大小写扩展名、符号链接循环、损坏书籍、未读状态、活动会话与进度不变、扫描不复制、读取时才导入、重新扫描去重、目的地再迁移、原副本丢失、不可用目录和保存失败时状态保留。
- Chromium 与 WebKit 各 14 组界面回归通过；新增覆盖多个来源配置、取消选择/编辑、仅保存不扫描、重启不扫描、重复扫描、最近阅读、打开书架时导入指令，以及错误和上限提示。
- TypeScript、前端隔离构建及 Clippy 通过。桌面 1180×800、900×700 检查长路径、多目录、焦点、禁用按钮、扫描结果和已有书库设置控件；未测试移动端。
- 浏览器的文件选择、扫描结果和 IPC 使用 mock；真实临时目录扫描、文件复制及持久化由 Rust 测试验证。没有将浏览器 mock 验证表述为对个人书库的真实扫描。

### 书架刷新验证

刷新功能在独立工作树与端口 1438 验证。Rust 临时 EPUB 测试覆盖原文件替换后的元数据更新、文件移除/损坏/恢复、活动会话不变，以及手动信息、进度、时长、收藏、置顶、标签和分组保留。浏览器 mock 回归覆盖空书架入口、来源发现和去重、扫描期间禁用与重复点击保护、失败重试、文件状态标记、封面缓存刷新、搜索保留，以及刷新不修改目录配置或打开阅读。

本次验证：23 个 Rust 测试通过，1 个导出器忽略；Chromium 与 WebKit 各 31 组回归覆盖通过，调宽排序框后相关 6 组 WebKit 回归再次通过。TypeScript、隔离构建和 Clippy 通过。实际检查 1180×800 与 900×700 的刷新焦点/禁用状态、状态提示、长搜索文本、排序框及缺失文件标记；未测试移动端。
