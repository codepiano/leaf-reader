# 第一版验证记录

日期：2026-11-08。平台：Apple Silicon / 8 GiB RAM / macOS 27.2。

## 隔离方式

源码目录起初为空仓库，没有此项目的在线服务。开发分支为 `codex/first-reader`。构建、Rust 测试、类型检查和浏览器验证均在 `/tmp/leaf-reader-validation` 的物理副本执行；依赖单独安装，没有指回源码目录的依赖链接。临时测试使用回环端口 1438，浏览器实例与存储独立，没有复用用户浏览器标签页。真实桌面应用使用 `LEAF_DATA_DIR=/tmp/leaf-reader-native-profile` 存放合成书籍和阅读记录。

## 自动检查

- TypeScript 检查、Vite 发布构建通过。
- `cargo test`：6 个测试通过，覆盖 ZIP 路径逃逸、EPUB 3 导航、带 DTD 的 EPUB 2 NCX、损坏 / DRM / 空书拒绝、惰性章节读取、阅读记录持久化和打开失败时保留原会话。
- `cargo clippy --all-targets -- -D warnings` 通过。
- Chromium：4 组浏览器测试通过。
- WebKit 27.2：相同的 4 组测试通过。
- 浏览器测试覆盖图片 / CSS、锚点、键盘和跨章链接、章内进度恢复、设置持久化、缺失章节报错后返回书架，以及书籍脚本 / 表单 / 外部请求隔离。正文确实不能访问父页面 DOM。
- 开发与测试服务器启用了 CSP，正文仅允许应用自带事件桥接脚本，不依赖开发环境放宽脚本权限。

## 桌面及视觉检查

此前已在真实 Tauri 发布应用中观察到：书架、示例书正文、图片及出版者 CSS、目录、字体下拉框、键盘选择、返回书架后的章节和章内位置恢复，以及通过原生文件选择器打开 64.1 MiB / 256 章合成 EPUB。

Chromium 与 WebKit 中检查了普通和长选项、焦点、禁用状态、主题切换、1180×800 与 900×700 桌面窗口。箭头有独立留白，长文字省略，不与箭头重叠。没有进行移动端测试。

真实 WebKit 验证发现无脚本 sandbox 的事件兼容问题，已改为不允许同源访问的 sandbox 加受 CSP 限制的应用事件桥；两种浏览器回归测试通过。最终普通发布包（未启用调试工具）已复核：滚动即时更新进度、书内链接跨章跳转、正文方向键切章、字体设置，以及关闭窗口前保存和重开恢复。关闭前第 2 章的章内比例为 0.37383177570093457，关闭后读取记录一致，原进程已退出；重开后原生滚动条恢复为 0.3738318，界面显示第 2 / 3 章、46%。64.1 MiB / 256 章合成 EPUB 的最终包显示和内存测量也已完成，见 `stress-book-memory.json`。诊断构建只用于排查，未进入交付包。

## 最终签名包性能测量

原始记录见 `performance-baseline.json`，记录了最终签名包的 SHA-256。测量时应用书架为空；系统与 WebKit 缓存、内存压力会影响结果，这些数据是本机观察值。

| 测量项 | 观察结果 |
|---|---:|
| 原生二进制 | 4,530,096 字节 |
| `.app` 大小 | 约 4.39 MiB |
| 第一次启动到界面就绪回执 | 1,991.8 ms |
| 后续四次启动 | 594.6 / 478.3 / 481.3 / 520.0 ms |
| 五次启动中位数 | 520.0 ms |
| 空书架物理内存中位数 | 86.3 MiB |
| 相同进程的 RSS 中位数 | 178.5 MiB |
| 最终包打开 64.1 MiB 合成 EPUB 后的物理内存 | 137.9 MiB |

启动时间从创建进程计起，到前端读取书架并经过两次动画帧后发回 IPC 就绪回执为止；这不等于操作系统冷启动。内存包括主进程、WebContent、GPU、Networking 四个进程；物理内存由 macOS `footprint` 测量，RSS 是另一口径，会重复计算共享页。XPC 服务由 launchd 托管，脚本通过启动前后的进程差异归属；测量期间没有主动启动其他 WebKit 应用。

尚未验证 Windows / Linux 运行、真实复杂排版书籍集合、DRM、固定版式、竖排和混淆字体的完整还原。交付副本完成本地 ad-hoc 签名，`codesign --verify --deep --strict` 通过；未进行 Developer ID 签名或公证，未安装至 Applications，未合并 main。
